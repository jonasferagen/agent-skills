# One project across repositories

A repository boundary does not necessarily define a separate project. Before
bootstrapping, establish whether this is an independent project, the shared
foundation owner, or a member of an existing project. Preserve an existing choice.

## Shared owners and local facts

Use the [foundation format and interpretation](foundation-format.md) for the
five-table shape, reference bindings and section inheritance. Bootstrap each
repository's local entry point. Shared owners hold project-wide decisions;
members declare section authorities and retain only local differences.

Detailed role assignments and handoffs remain in their architecture owner,
linked from boundaries. Internal design and commands belong to the implementing
repository's architecture and procedures. Plans, evidence and status retain their
own homes. Scope shared technical choices explicitly; a coordinator's own stack
or packaging is not automatically a choice for its members.

## Instructions and access

AGENTS owns the local lookup hook and missing-owner behavior. Shared working
agreements can own full workflow routes. Foundation tables contain declarations
and project facts only; do not put reference tutorials or skill routes there.
Each independently usable repository declares its external root once. If an
existing configuration owner already holds the value, reconcile that ownership
before adopting this format; do not silently create a second authority.

## Workspace entry

When agents start above the member repositories, give that workspace an AGENTS
entry and a short README within the authorized setup scope. Route to the shared
owner's instructions and installed collection for workflow selection, then to the
target repository's instructions before repository-specific work. Reading a route
does not require loading every skill. Keep existing member entry hooks usable
for agents that start directly in a repository.

Name participating repositories and the authority for membership. Filesystem
ancestry alone does not adopt shared policy for legacy or unrelated repositories.
Do not copy foundation decisions, skill catalogs or installations into the parent.
A routing-only workspace needs no separate foundation or Git repository.

If the parent is untracked, keep entry files in a selected tracked repository and
expose them with symlinks when supported. State the base for relative links:
workspace-facing entries resolve from the exposed workspace root, even when an
agent reads their tracked source. Keep source maintenance instructions beside
them. Other clients may need concrete files; derive or check those copies and
record the mechanism instead of claiming automatic discovery. A symlink into an
absent owner also removes the entry hook; record that dependency, and use derived
concrete hooks if offline entry instructions are a requirement.

Inspect existing parent files before installation. Preserve useful facts and
historical evidence, and do not replace an unrelated instruction owner. Install
links only after their tracked targets are available. Verify exposed paths,
symlinks and relative routes from the workspace and the tracked source context,
plus ordinary member and task-worktree entry. Keep missing-authority behavior
locally readable; defer only work needing the unavailable owner. Report which
filesystem routes were checked separately from actual client discovery.

## Collection and access

Document ownership and skill distribution are separate choices. One complete
collection in the shared owner can serve members with access. Route through the
named root to that installation and keep provenance with it. Separate pinned
installations are valid when independent checkout or execution requires them;
they must not create competing project decision owners.

Declare in project instructions whether consumers read the shared main checkout
or a selected snapshot.
Do not silently substitute another task's unlanded work or a stale copy. A snapshot
needs its revision and update mechanism recorded. If authority is unavailable,
report the missing dependency and defer decisions needing it. Preserve unrelated
authorized work. Record access from main checkouts, task worktrees and relevant
execution environments; untested environments stay explicit gaps.

## Reconcile and verify

Compare values before removing copies and preserve unique facts in their owners.
Repair active README and agent routes; retain dated evidence as history.
Verify that a shared change reaches members, a local choice leaves other members
unchanged, an explicit unknown remains visible, and conflicting or unavailable
authority cannot silently authorize work. Test changing only the binding in an
isolated copy and following its routes from main and actual nested worktrees.
Check section anchors as well as files. Report what was exercised and what was
only reviewed; bootstrap establishes documents and routes, not automatic runtime
inheritance or proof of compliance.
