# Capture friction during work

Use this reference when actual work exposes unnecessary reading, conflicting
instructions, repeated clarification, awkward tooling, duplicated edits or a
workaround. Routine successful work needs no capture pass or “no friction” report.

At a natural checkpoint, record the task, observed obstacle, consequence and
workaround or unresolved question in the project's existing experiment or work
notes. Include the source path when it helps reproduce the problem. Create a
small friction note only when an observation needs a durable home. Keep private
input out of examples. Mention material friction in the hand-back.

Separate observation from diagnosis and a proposed fix. Fix a clear, in-scope
local problem when authorized; keep uncertain generalizations as candidates.
Do not interrupt useful work to reorganize the skill library or create a new rule
for each inconvenience. A missing project decision is not automatically a skill
defect. Avoid logging ordinary choices as friction unless they caused a concrete
cost or mistake.

When repeated cost or a serious failure warrants reusable guidance, use
pattern-capture if available, or record the candidate and evidence still needed.
Source provenance can locate the authoring home for that follow-up; it is not a
reading prerequisite for ordinary capture. This collection does not require
installing pattern-capture just to record an observation.
