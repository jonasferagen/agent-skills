# Authoring project documents

Use [clear-writing](../skills/clear-writing/SKILL.md) when drafting or editing
project prose. For agent instructions, also use its
[instruction guidance](../skills/clear-writing/references/instructions.md).

Before a substantive explanation, use
[diagrams-and-tables](../skills/diagrams-and-tables/SKILL.md) to choose whether
prose, a table or a diagram carries the information best. Follow its references
for the selected form. Rendering mechanics are needed only when creating or
changing a diagram; ordinary table edits need no Mermaid tooling.

Preserve adopted decisions and uncertainty. The scaffold's blank cells mean
unknown. Populate only what the user's decisions or repository evidence supports;
mark consequential unknowns explicitly with what depends on them. Keep reusable
instructions in the collection and project facts in the project documents.

Set template dates to the date of establishment and revisions to 1. On a
substantive document change, update the date and increment its revision. A
wording-only edit need not change the revision. These identify the document's
decision state, not implementation readiness or evidence of compliance. Preserve
an existing project's revision convention when it has one.
