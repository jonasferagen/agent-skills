# Discover policy requirements

Use this for establishment, adequacy review or when changed circumstances require
new decisions. Start with the current facts, relevant boundaries and a concrete
intended use. A focused adequacy review needs only its affected scope; a full
profile review also checks the axes in [establishment](establish.md#policy-axes).

Trace a concrete use through the people relying on it, the state it retains and
the actions it permits. Ask where an owner would have to guess a required outcome
or where the same stated facts could lead to incompatible obligations. Use relevant
policy axes as prompts; a filled table alone does not establish that the important
decisions are covered. Include a domain-specific circumstance when it changes a
concrete requirement, even if these instructions do not name it.

For each consequential unknown, identify the missing decision, affected use,
responsible owner and work that depends on it. Propose requirements using available
evidence and existing authority; distinguish them from adopted decisions. Keep
unaffected work moving. An unavailable verification result is an evidence gap,
not grounds to weaken the requirement.

Record findings against their source facts and affected owners. For changed use,
continue through [policy changes](policy-changes.md) to assess consequences and
readiness. For unchanged use, report missing decisions and evidence without
inventing a transition. This assessment alone does not authorize adoption or execution.
