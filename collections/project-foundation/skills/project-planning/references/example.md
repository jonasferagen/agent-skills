# A small shared plan

This synthetic example illustrates a plan with two repository owners. Adapt the
fields and document layout to the project; no tracker or separate plan file is
required for each item.

## Outcome and scope

Demonstrate one retained document in a fresh viewer session. Source adoption and
a local import are in scope. Remote conversion and a general catalog are deferred.
The architecture owner defines the Producer and Viewer responsibilities.

## Active work

| Item and owner | Result and completion evidence | Dependency and next action | Status |
| --- | --- | --- | --- |
| Source inventory — Viewer | Selected source and helpers mapped to their intended homes, with preservation and startup checks identified | Retained source is available; inspect it and record the selection | Ready |
| Sample export — Producer | One candidate with input identity and an output record; review evidence remains separate | Needs the requested input/output requirements; obtain them from the requesting owner | Blocked on requirements |
| Fresh-session import — Viewer | Selected output opens in a fresh session and a local adaptation survives an update | Needs selected source and a reviewed sample; detailed steps belong in Viewer's procedure | Waiting on those results |

The inventory can proceed while export requirements remain unresolved. The shared
plan owns these statuses; local design pages link these items and explain their
prerequisites. If local queues already existed, this page would link their items
instead of copying their changing statuses.

## Deferred work

A general catalog is reconsidered when several consumers need independent
selection histories. It does not block this single-document demonstration.
Remote conversion is reconsidered if the sample cannot be produced locally;
choosing it would still require its actual execution prerequisites.

## Example update

If the inventory discovers an incompatible helper, retain the selected source
mapping as partial evidence and make compatibility checking the next action.
Only dependent startup work waits. If the sample is exported but has not been
reviewed, record export completion while keeping import's reviewed-sample
dependency open. Put the dated finding in the project's work record and update
this active table; do not leave both old and new next actions in circulation.
