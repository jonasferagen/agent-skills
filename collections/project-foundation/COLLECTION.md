# Project foundation

Start with project instructions and their existing document routes. Use this
entrypoint to choose needed guidance; if the owner and workflow are already known,
follow them directly. Source-maintenance guidance and provenance are needed only
for source changes, upgrades or investigation of a concrete source issue.

| Task | Entry point |
| --- | --- |
| Interpret foundation declarations and inherited values | [Foundation format](references/foundation-format.md) |
| Start the project foundation | [Project bootstrap](skills/project-bootstrap/SKILL.md) |
| Shape architecture, responsibilities, workflows and integration choices | [Project design](skills/project-design/SKILL.md) |
| Read, apply, design or review handoff obligations | [Project contracts](skills/project-contracts/SKILL.md) |
| Start or resume edits and preserve repository work | [Git worktrees](skills/git-worktrees/SKILL.md) |
| Interpret policy, assess compliance or review changed circumstances | [Project policy](skills/project-policy/SKILL.md) |
| Organize and reconcile project documents | [Project documentation](skills/project-docs/SKILL.md) |
| Keep authoritative decisions and their consumers aligned | [Source of truth](skills/source-of-truth/SKILL.md) |
| Write clear prose | [Clear writing](skills/clear-writing/SKILL.md) |
| Read, review or construct diagrams and tables | [Diagrams and tables](skills/diagrams-and-tables/SKILL.md) |
| Record an observed obstacle during work | [Friction capture](references/friction.md) |

Load only the route needed by the question. For reading or applying an existing
document, use its authoritative owner, relevant terms and available evidence.
Unknowns stay unknown; proposals and adopted obligations remain distinct from
verified behavior. A focused answer or literal wording edit needs no authoring
workflow. A change to meaning uses its owning workflow.

Use [foundation authority](references/foundation-authority.md) when establishing
or reconciling decisions, resolving conflicting authority, or assessing changed
scope or circumstances. A narrow task within known constraints does not require
loading that reference. Follow declared inheritance through
[foundation format](references/foundation-format.md) when the answer depends on
it; unavailable owners or unknown terms do not grant permission or waive obligations.

For authored or restructured explanations, use
[shared authoring guidance](references/authoring.md). Edits in Git repositories use task
worktrees unless repository-local instructions explicitly opt out. Work outside
Git proceeds directly.

For adoption, upgrades, installation locations or templates, use
[installation guidance](references/installation.md) and bootstrap. Routine use
of an installed collection needs neither setup nor every skill loaded.
