# Project planning

Make the next useful result and its prerequisites clear. Start from the requested
outcome, current project scope and existing planning owner. Follow the project's
plan home and template when selected; an adequate tracker or existing plan can
remain authoritative. This skill requires no particular format or companion.

## Select the task

- For a next-step decision or uncertain sequence, read
  [choosing the next step](references/next-step.md).
- For a new plan or substantial restructure, apply the structure and ownership
  guidance below. Use the [small example](references/example.md) if helpful.
- For progress maintenance, update the affected item and its dependents. A
  routine status lookup needs only the existing owner; do not replan the project.
- For a review, compare the plan with its inputs and report findings. Review
  alone does not authorize rewriting the queue or executing it.

## Make work actionable

Describe the outcome and bounds of the plan. Link current policy, design and
interface owners instead of copying their definitions. Distinguish a proposed
sequence from work already selected by the project. Add detail near the next
decision; later possibilities need only enough detail to preserve their intent.
Do not invent estimates, dates or commitments to complete a template.

For each active item, make these answers available together:

- What useful result is expected, and who owns delivering it?
- Which inputs or prerequisite results does it need, and are they available?
- What is its current status and next concrete action?
- What evidence will establish completion at the requested scope?

These answers can fit in an existing task or short paragraph. A routine fix
does not require a new document or a mandatory record chain. Name unknown
ownership explicitly rather than assigning an unconsulted person.

Sequence actual prerequisites. A list order, architectural layer or repository
name alone is not a dependency. Independent work can proceed when its inputs are
ready. State the missing input for blocked work and which result it prevents.
For a deferred question, record its revisit condition and affected work; do not
turn every open choice into an immediate gate.

## Keep one coordination owner

Each action item has one authoritative status and next action. Shared plans
coordinate cross-owner outcomes and prerequisite results; local plans own their
detailed work. Link delegated items instead of copying their changing status.
If a brief or tracker owns the same assignment, link it as that item's owner.
Reconcile competing queues by preserving unique work and choosing the owner
before retiring a copy. Do not silently delete an unresolved obligation.

Policy owns adopted constraints, design owns current structure, and the plan
owns pending work. If the chosen work changes operating facts or obligations,
use the project's policy workflow and include dependent implementation and
verification work. A proposal does not itself amend current policy or design.
Missing guidance or evidence blocks only work that requires it.

## Maintain and verify

On progress, record the actual result and evidence and update affected dependents.
Design completion is not implementation completion; a partial result leaves a
usable next action. Put dated observations and detailed history in the project's
work records and link them. Keep the active plan concise; remove obsolete next
actions and retain a reason or replacement link for cancelled or superseded work.

Trace a representative item from prerequisites to result and evidence, including
any downstream consumer. Check that its next action is possible or its blocker
explicit, that deferred choices have revisit conditions, and that coordination
has one owner. Follow the project's writing and verification guidance for the
authored material; report checks performed and remaining uncertainty.

A plan proposes or records coordination. It adds no execution permission, new
approval gate or publication requirement; follow the task's existing authority.
