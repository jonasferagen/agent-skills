# Read a swimlane activity view

Use this form to explain work crossing responsibilities, including work performed
by agents following instructions. Read the caption and legend first. Lanes may
identify performers or accountable owners; the view must say which. Do not assume
those are the same, or that a lane denotes a deployed service or repository.

Read each activity as an action and its stated method: for example, an agent
follows a procedure, invokes a command, or uses a service; a person makes a
specified decision. These properties can overlap. An instruction document is a
source for work, not an executing participant. A lane alone does not establish
how its activity is performed, decision authority or implementation status.

Follow arrow labels for the result or condition passed onward. Crossing a lane
states only the declared flow; it does not establish an HTTP call, shared storage,
permission, acceptance or safe retry. A decision belongs to its stated decision
maker. Human involvement is not automatically an approval gate, and an agent can
hold delegated decision authority. Completion, acceptance and consumer adoption
remain distinct when the process distinguishes them.

For an overview, explain who receives what, what they do and what allows work to
continue. Link to the owning procedure or interface when the view does not show
how. Preserve missing or proposed details as such; do not fill them from familiar
agent architectures.

Use [form selection](../select.md) for another question and
[construction](design.md) only when creating or changing the view.
