# README routing

Use this guidance when designing or restructuring a README or documentation
entrypoint. The consuming project owns filenames, document locations, required
entrypoints and enforcement. Preserve those contracts; do not prescribe a new
project layout merely to shorten a page. If the entrypoint contains rules or
procedures, also read [writing instructions](instructions.md) to preserve their
force and authorization boundaries.

## Orient and route

Help a reader identify what this unit owns, its public surface, where to go for
their task and how ordinary verification works. Keep essential common limits
visible at entry. Put a conditional obligation beside the route that triggers it,
and retain its full procedure with the authoritative owner. A task label should
explain when to follow a link; link directly to the relevant guide or section.

Use a short task list or table when it improves selection. Keep a useful catalog
at entry when discovering its items is the reader's task. Avoid turning every
folder into another index or making a reader traverse several pointers to reach
one answer. A short unit may need only a few paragraphs; there is no universal
heading template, word limit or requirement for a separate guide.

## Give each answer an owner

Before moving prose, identify the document that owns the answer. Reuse it when
it fits. Split a long page only where tasks or audiences need distinct guidance.
Keep component detail with its component, shared procedures with their shared
owner and reusable methods with their package. Project-specific obligations stay
in project instructions. A README's short route must not become a competing
summary of parameter lists, contract fields or another guide's procedure.

Keep instruction entrypoints authoritative for agent obligations. A README can
route to them but cannot replace them. Readers follow applicable instructions
first, then inspect headings and read the sections their task requires, including
prerequisites and mandatory references. Selective reading never waives a rule.

## Preserve and verify the routes

Inventory incoming links and established anchors before moving content. Update
known callers and retain useful compatibility anchors for published links when
callers cannot all be updated. Rebase relative links in moved prose. Avoid a loop
where an owner sends the reader back to an index that only points to that owner.

Compare the result with the source: preserve scope, prerequisites, ordering,
exceptions, failure and recovery obligations, and what a check does or does not
establish. Verify link targets and anchors as well as reachability from the normal
entrypoint. Document existence alone does not prove that a reader can find it.

For a material routing change, try ordinary entry, a task requiring deeper
guidance and nearby work that should stay narrow. Use fresh readers or agents
without expected answers when available. Observe actual routes, missed obligations
and unnecessary reading; a smaller README alone is not evidence of better
routing. Keep test cases separate from observed results and record limitations.
