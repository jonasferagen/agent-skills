# Project contracts

Make clear what participants can rely on at a handoff. Start with the user's
question, the authoritative agreement and its applicable revision. Distinguish
proposed terms, adopted obligations and observed behavior. Follow the project's
policy and authority when resolving conflicts or changing obligations; this skill
requires no particular document structure or companion installation.

## Select the task

- **Read or explain:** Answer from relevant terms and linked definitions. Cite
  what supports the answer and distinguish explicit obligations, interpretation
  and ambiguity. Missing terms remain unresolved; a reading task needs no redesign.
- **Apply:** Compare a request, result or action with applicable terms. Report
  satisfied, violated or unverified conditions. Missing terms supply no acceptance
  criteria; applying an agreement grants no execution or adoption permission.
- **Design or change:** Use [contract design](references/design.md) to discover
  obligations, propose terms and assess changes to existing agreements.
- **Review:** Use [contract review](references/review.md) to assess the agreement
  for the requested purpose and report findings.

Load only the reference the task needs. A wording correction uses ordinary editing
guidance. If the question is which responsibilities should exist, use the project's
architecture workflow; project-design is suitable when available. A document
handoff needs neither an API nor a machine-readable schema.

## Handle gaps and finish

For a missing term, name the unresolved decision, consequence, responsible owner
and dependent work. During reading or application, report the limit without
silently supplying a rule. During design, propose or establish terms within the
task's authority and known constraints. Ask only when the current task needs the
answer; continue unaffected work.

Keep agreements with their existing owners and use the project's document homes
and templates for new ones. Templates help readers find terms; filled headings
do not establish completeness. Implementation procedures, formats and actual
exchange evidence retain their own owners. Link exact input and agreement
revisions when judging a particular result.

Report conclusions, relevant cases and evidence limits. A schema check or tool
success cannot prove fulfillment of every obligation. Follow the project's
writing and reconciliation guidance for authored changes. A missing project term
is not automatically a defect in the skill; consequential guidance problems use
the project's declared capture and repair route.
