# Project design scenarios

Requests, context and expected behavior this skill is evaluated against. Use them
when changing the skill; ordinary use of the skill does not read them. Record a
run's observed results with the change that ran it, not here.

## Cases

| Request and context | Route | Expected behavior |
| --- | --- | --- |
| Shape a repository whose output is design decisions | Entry point, then workflows | A manual document process is a valid mechanism; no service, runtime or deployment is inferred. |
| Distinguish a lending title, a physical copy and a loan | Entry point, then conceptual models | Independent lifecycles explain identity; a returned damaged copy need not be available. No database schema is selected. |
| Separate runtime code from authored content | Entry point, concrete normal and change cases | Trace content-only and runtime changes, preparation writes and compatibility before choosing another repository or container. |
| Compare ways to execute a selected operation | Entry point, then integrations | Compare manual and local options, authority, effects and evidence; no provider guarantee or execution permission follows from a proposal. |
| Sequence an experiment and the implementation that depends on it | Entry point, then the project's planning workflow | Use the project's planning home and link its active queue; add no second status owner and require no companion skill. |
| A design changes an adopted obligation | Entry point | The policy owner is consulted; document adoption does not establish implementation. |
| Evidence for one choice is missing | Entry point | Only the dependent choice waits; the rest of the design proceeds. |
| Interpret one existing handoff term | The existing agreement, or project-contracts | No architecture redesign or full integration pass. |
| Correct a label in a current guide | The existing document and writing guidance | No design reconstruction or format migration. |

## Limits

- The cases are author-reviewed route and artifact traces. Independent cold-entry
  and nearby-negative activation have not been exercised.
- A design owner can produce decisions and artifacts without acquiring a runtime;
  the skill supplies reasoning, and templates belong to the consuming project.
