## Practical routing evidence

Five fresh contexts started at synthetic consumer AGENTS hooks outside the
authoring repository. Each received only its fixture path, normal task request,
resource limits and a request to record actual reads. No suspected defect,
expected route, answer or missing-guidance report was supplied. The source and
consumer installation were separate; source repairs had isolated task worktrees.
[Selected inputs, outputs and execution records](passive-guidance-repair-trial/README.md)
are historical evidence, not current setup instructions.

- **Ordinary read without source delegation:** explained acceptance and corrected
  a typo. Did not traverse the seeded status-reference defect or enter source
  maintenance. The guidance subtotal was 1,190 words, excluding the request and
  output verification. This exercises conditional nonactivation, not detection.
- **Read with standing source delegation:** encountered the seeded status-reference
  defect, completed the original task and recorded its consequence. Corrected
  the source link in a worktree and locally landed `5c13806`. The installed
  collection and consumer pin remained unchanged.
- **Missing project term:** stated that retries under the same request ID were
  unspecified, preserved the agreement and corrected the independent typo.
  Read 1,780 guidance words. Did not treat the project gap as a skill defect or
  load friction, source provenance, design or review guidance.
- **Deeper review without source delegation:** encountered a broken review link,
  found the existing review reference, recorded a concrete source repair candidate
  and completed the timeout/retry assessment. Source and installation were unchanged.
- **Deeper review with standing source delegation:** reproduced the broken review
  link in installed and pinned source, completed the assessment and corrected the
  source route in a worktree. Locally landed `65283e3`; consumer adoption remained
  separate. Required deeper contract guidance was reached through the workaround.

The coordinator checked all five consumer installations byte-for-byte against
their initial synthetic source pins. All were unchanged; agreements were preserved
and every note had only the requested typo correction. Both authorized repairs
changed the source route and its validation record, without upgrading consumers.

## Review and checks

Independent meaning review confirmed the nine entry hooks and the preserved
project/evidence/guidance distinctions. It found an overly broad prohibition on
capturing defects in the capture process; the final wording forbids repeated
maintenance for the same finding and recursive repair spawning while preserving
capture of distinct demonstrated defects. The reviewer rechecked that correction.
The Forge route also requires the complete new installation before its delegation
lands; that adoption is a separate, authorized part of this task.

Source package validation passed for 25 entries and one collection. All nine
changed skill manifests passed skill-creator validation. Changed-document links,
anchors and whitespace were checked. No helper implementation changed.

The synthetic repair sources omitted the standalone-package tree expected by
the copied full validator entrypoint. Both repair agents recorded that fixture
limit rather than broadening the repair. They exercised the existing collection
manifest/link checks directly, plus whitespace and route cases. This establishes
collection-scoped checks, not a successful full-validator invocation in those
fixtures; the full validator passes in the real authoring repository.

## Limits

These are configured consumer routes and simple reproduced link defects. They
do not establish native client discovery, reliable detection of every omitted
obligation, broad redesign quality or unattended/background execution. Passive
capture cannot detect an untouched route, as the ordinary read demonstrates.
Delegated repair execution, concurrent writers, deduplication across repeated
real tasks, source unavailability and the final distinct-self-defect rule were
not behaviorally exercised. The latter was checked by independent comparison.
Practical usage is the next evidence for reliability and overhead. No release tag
or external publication was created.
