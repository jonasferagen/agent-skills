# Tools context

Tools owns external execution and candidate evidence. Assets supplies a brief,
receives retained candidate bytes and decides creative acceptance. Game adoption
is separate. This fixture has no code, chosen language, credentials or spending
budget. Local host execution is the intended first environment. A persistent
service, queue, general asset store and database remain unselected.

The requested result is a proposed design, using a synthetic brief. Actual Forge
work still needs a real generation brief, exact output requirements, permitted
input data, access and spending scope. Keep those limits visible.

Use brief.md for the requested candidate, provider-evidence.md for the bounded
provider facts, and handoff.md for the proposed exchange. Candidate output and
execution evidence roots must be explicit inputs. Original sources and accepted
asset revisions are outside Tools' write scope.
