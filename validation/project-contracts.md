# Project contracts validation

Draft versions: project-contracts 0.1.0 and project-design 0.3.0, 2026-10-03.

## Intended routing and behavior

- Choose responsibilities or sketch how components relate: project-design.
- Define or revise what producer and consumer may rely on: project-contracts.
- A document, file or agent handoff receives the same ownership and acceptance
  scrutiny without acquiring an API or formal schema.
- Assess changed operating obligations: project-policy, from the affected terms.
- Select/render a visual: diagrams-and-tables; it does not own architecture.
- Correct literal wording or discuss legal agreements: no contract-design route.

The scope remains one new member in the existing collection. Existing design
callers can reach the contract skill through project-design; no installation unit
or project foundation format changes. The standalone service-boundaries skill
keeps its narrower service and transport implementation scope.
